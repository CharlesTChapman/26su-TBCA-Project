# TBCA: European Higher Education Explorer

Every year, students are tasked with picking the right university for them, without knowing how the job market will look when they graduate. They bet several years of their lives and tens of thousands of euros on an education they don’t even know will pay off.

Here at TBCA, we have the solution. Our application connects EU university data with a decade of Eurostat labor statistics to help students, labor statisticians, and budget planners make the right decisions. 

Students get a personalized university list, labor statisticians get a live market prediction model, and budget planners can trace funding directly to outcomes.

There’s no longer a need to stress about the future, because we at TBCA are here to help.

## Features

The app is organized around three user personas, each with its own home page and
toolset.

### Student
- Fill out a preferences survey: budget, degree level, preferred size, major,
  country, commute range, campus type, and financial-aid status.
- Get a ranked list of recommended universities generated by a machine-learning
  model that scores each school against the survey answers.
- Browse the full university catalog and open detail pages with tuition, fees,
  staffing, and degree information.
- Save universities to a favorites list.
- Keep personal pros-and-cons notes on any university.
- View and edit your own profile information.

### Labor Statistician
- Explore employment observations broken down by country and industry sector.
- Run a predictive model that can estimating employment level in a selcted year, and estimate
  year-over-year employment change.
- Review labor-market absorption rates.
- Add, update, and delete observation records.

### Budget Manager
- Review university budget plans and total allocations.
- Drill into per-university budget details.

## Tech Stack

| Layer        | Technology   | Host Name : Port
| ------------ | ------------ | -----------------
| Frontend     | Streamlit    | web-app:8501
| REST API     | Flask        | web-api:4000
| Database     | MySQL        | db:3306

The Streamlit app talks to the Flask API over HTTP, and the API is the only layer
that reads from and writes to MySQL. Both predictive models are served through the
API, the university recommender ranks schools by cosine similarity to a student's
survey, and the labor models are linear regressions over historical employment data.

## Getting Started

You need [Docker](https://www.docker.com/) installed. Everything runs in containers,
so you do not need Python or MySQL on your machine.

1. **Clone the repo**

   ```bash
   # Clone the repository
   git clone <git@github.com:CharlesTChapman/26su-TBCA-Project.git>
   # Open the repository
   cd 26su-TBCA-Project
   ```

2. **Create the environment file**

   Copy the ***.env.template*** file in our ***api*** folder

   ```bash
   cp api/.env.template api/.env
   ```

   Open `api/.env` and set a value for each placeholder:

   ```
   SECRET_KEY=<a random string>
   MYSQL_ROOT_PASSWORD=<a strong password>
   ```

   The remaining values (`DB_USER`, `DB_HOST`, `DB_PORT`, `DB_NAME`) can be left as is
   becuase they are for local development.

3. **Start the containers**

   ```bash
   docker compose up -d
   ```

   This builds and starts three services: the Streamlit app, the Flask API, and the
   MySQL database. The database is filled automatically from the scripts in
   `database-files/` on first start.

4. **Open the app**

   | Service        | URL                     |
   | -------------- | ----------------------- |
   | Streamlit App  | http://localhost:8501   |

To stop everything, run: 

```bash
docker compose down
```


## Using the App

1. Open http://localhost:8501 in your browser.
2. On the home page, pick a persona — Student, Labor Statistician, or Budget
   Manager — and select an account to log in as.
3. Each persona lands on its own home page with the features listed above.

We have ***yet*** to implement a form of authentication, but hope to eventually. We made **personas** and **mock users** to simulate user data and login features that are personal to each individual.
